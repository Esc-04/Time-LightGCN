# Gowalla Dataset with Temporal Information

Time-LightGCN 실험용 데이터셋입니다. LightGCN 저자 배포본에 시간 정보(Δt)를 추가했습니다.

---

## 파일 구성

| 파일 | 컬럼 | 행 수 | 용도 |
|---|---|---|---|
| `gowalla_train.parquet` / `.csv` | user, item, dt_days | 810,128 | 학습 |
| `gowalla_test.parquet` / `.csv` | user, item | 217,242 | 평가 |

- parquet: 빠른 로딩용 (`pd.read_parquet`)
- csv: 내용 확인용 (드라이브에서 클릭하면 바로 보임)
- 두 파일 내용은 동일합니다.

---

## 컬럼 설명

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `user` | int | 유저 ID (0 ~ 29,857) — **저자 배포본 remap_id와 동일** |
| `item` | int | 아이템 ID (0 ~ 40,980) — **저자 배포본 remap_id와 동일** |
| `dt_days` | int | Δt, 일 단위. 해당 유저의 **train 내 마지막 상호작용 시점**으로부터 며칠 전인지 |

**dt_days 예시** (유저 101)

```
기준점 = 2010-10-20 (이 유저의 train 마지막 방문일)

item 791  방문 2010-10-20 → dt_days = 0    (가장 최근)
item 6146 방문 2010-10-18 → dt_days = 2
item 4608 방문 2010-10-16 → dt_days = 4
...
item 1553 방문 2010-01-10 → dt_days = 283  (가장 오래됨)
```

- 값이 **작을수록 최근**, 클수록 과거
- train의 dt_days는 항상 **0 이상** (기준점이 train 내 최댓값이므로)
- **기준점은 유저마다 다릅니다.** 각 유저의 마지막 활동이 그 유저의 t=0

## 전처리 과정

### 1. 원본 다운로드

SNAP Gowalla 체크인 데이터 (`loc-gowalla_totalCheckins.txt`, 6,442,890건)

```
[user] [check-in time] [latitude] [longitude] [location_id]
196514  2010-07-24T13:45:06Z  53.36  -2.27  145064
```

- `location_id`를 아이템으로 사용
- 위경도는 사용하지 않아 제거

### 2. 중복 제거

한 유저가 같은 장소를 여러 번 방문할 수 있으나, LightGCN의 이진 그래프에서는 (user, item)이 유일해야 합니다.

**규칙: 가장 최근 timestamp를 선택**

- 근거: 유저의 현재 취향에 가장 가까운 시점이 우리 가설과 부합
- 결과: 6,442,890 → 3,981,334건

### 3. 10-core 필터링 (검증용)

LightGCN 논문은 NGCF 데이터셋을 그대로 사용했다고만 서술하며, 전처리 기준은 NGCF 논문 4.1절에 명시되어 있습니다.

> 데이터 품질 보장을 위해 10-core 세팅을 사용한다 — 최소 10개 이상의 상호작용을 가진 유저와 아이템만 유지

**중요: 반복(iterative) 적용 필요**

유저를 제거하면 일부 아이템이 10개 미만이 되고, 그 아이템을 제거하면 다시 일부 유저가 10개 미만이 되는 연쇄가 발생합니다. 변화가 없을 때까지 반복해야 합니다.

```
[1회]  3,981,334 → 1,315,047
[2회]  1,315,047 → 1,087,284
...
[11회] 1,027,464 → 1,027,464 (제거 0, 종료)
```

**재현 검증 결과**

| 항목 | 직접 구현 | 저자 배포본 | 비교 |
|---|---|---|---|
| 유저 | 29,858 | 29,858 | **ID 단위 완전 일치** |
| 아이템 | 40,988 | 40,981 | 7개 초과 (누락 0) |
| 상호작용 | 1,027,464 | 1,027,370 | 94개 차이 |

아이템 7개 차이는 중복 체크인 처리 방식의 미세한 차이로 추정됩니다. 저자에게만 있는 항목은 0개이므로 누락은 없습니다.

### 4. 저자 split 적용

train/test 분할은 랜덤 요소가 있어 직접 나누면 저자와 달라집니다. 그 경우 팀 내 바닐라 실험 결과와 비교가 불가능해집니다.

**해결: 저자 배포본을 그대로 사용하고 시간만 추가**

1. `user_list.txt`, `item_list.txt`로 remap_id ↔ 원본 ID 매핑 (매핑 실패 0건)
2. 저자 `train.txt` / `test.txt`의 (user, item) 쌍을 그대로 유지
3. 각 쌍에 원본 데이터에서 조회한 시각을 붙임
4. train 기준으로 Δt 계산

**결과: user/item ID와 split이 저자 배포본과 100% 동일. 시간 컬럼만 추가됨.**

### 5. Δt 계산 — 데이터 누출 방지

기준점을 잘못 잡으면 test(정답)의 시점 정보가 train에 유입됩니다.

**잘못된 방식 — 전체 데이터의 마지막 시각 기준**

유저 A의 train이 6월까지, test가 9월인 경우 전체 기준점은 9월입니다. 이때 train의 Δt를 계산하면 모든 값이 "9월로부터 며칠 전"이 되어, 모델이 학습 중에 **"이 유저는 9월에 활동한다"**는 정답의 시점 정보를 간접적으로 알게 됩니다.

**올바른 방식 — 유저별 train 내 마지막 시각 기준**

```python
t_ref = train.groupby("user")["time"].transform("max")
train["dt_days"] = (t_ref - train["time"]).dt.days
```

기준점이 train 안에 있으므로 test 정보가 전혀 사용되지 않습니다.

**test에 dt_days를 넣지 않은 이유**

- 평가 시 test 아이템의 시각은 모델 입력이 아님 (추천 목록 상위 포함 여부만 평가)
- 컬럼이 존재하면 실수로 모델에 투입될 위험이 있고, 그 순간 누출이 발생
- 파일 구조 자체로 "시간은 학습에만 사용"을 강제

## 저자 split 분석 — 시간순 분할

저자 배포본의 split을 분석한 결과, **랜덤 분할이 아니라 시간순 분할**임을 확인했습니다.

```
유저 0
  train: 2009-03-08 ~ 2010-03-29  (127개)
  test : 2010-03-29 ~ 2010-09-25  (32개)
  → test 최소 > train 최대: True

유저 1
  train: 2009-03-08 ~ 2010-09-28  (49개)
  test : 2010-09-28 ~ 2010-10-12  (13개)
  → test 최소 > train 최대: True
```

검사한 모든 유저에서 test 구간이 train 구간 이후에 위치합니다. NGCF 논문 본문에는 랜덤 선택으로 서술되어 있으나, 실제 배포 데이터는 시간순으로 분할되어 있습니다.

**연구상 함의**

정답(test)이 미래에 위치하므로 "과거로 미래를 예측"하는 세팅입니다. 이 경우 최근 상호작용이 미래 예측에 더 유용하므로, 시간 가중 모델링의 효과가 성능 차이로 드러날 여지가 큽니다.

반대로 랜덤 분할이었다면 정답이 과거에 흩어져 있어, 시간 순서를 알아도 이득이 제한적이었을 것입니다.

**주의점**

시간순 split은 순차추천(SASRec 등) 세팅에 가깝습니다. 다만 본 연구는 시퀀스 모델링을 하지 않으며, 평가 프로토콜은 표준 all-ranking top-K(Recall@20 / NDCG@20)를 유지합니다. 또한 이 split은 비교 대상인 바닐라 LightGCN에도 동일하게 적용되므로 비교의 공정성에는 문제가 없습니다.

## 사용 예시

```python
import pandas as pd

train = pd.read_parquet("gowalla_train.parquet")
test  = pd.read_parquet("gowalla_test.parquet")

print(train.head())
#    user  item  dt_days
# 0     0     0       94
# 1     0     1       38
# 2     0     2       11

# 모델에서 Δt 사용 예
# mul: alpha = exp(-lambda * dt_days)
# add: e_i + beta * Phi(dt_days)
```

**단위 주의**: dt_days는 일(day) 단위입니다. 초 단위를 사용할 경우 값이 지나치게 커져 exp 계산이 0으로 수렴할 수 있습니다.
